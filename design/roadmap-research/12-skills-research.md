# Skills: comparative research

**Roadmap item 12 · 2026-09-28.** Source review of pinned local checkouts; no live turn or production-data probe was run. “Implemented” describes the inspected code, not verified deployment. Paths are relative to each named checkout.

## Dashi baseline

At 018af90, Dashi defines a skill as named task instructions loaded when invoked (design/ubiquitous-language.md:27) but has no skill package (design/remaining-work.md:139-148). A host can already set Agent.Instructions, bind a tool.List, join Toolsets with duplicate-name detection, and construct a local typed tool (turn.go:23-45; runner.go:21-39; tool/tool.go:489-547; tool/function.go:33-77). Tool calls and results are committed Turn facts; ToolPlan.Turn.Tools projects settled outcomes to hooks (state.go:41-70; hooks.go:289-302). Only ContextOperator can speak with system/developer authority; a loaded body should remain a tool result (context_origin.go:5-30). Agent.Revision cannot automatically include tool behavior (turn.go:27-31). A zero Runner.Agent on Continue uses the recorded agent, so a changed tool bundle can escape that comparison unless the host pins the bundle too (defaults.go:96-160).

## Real consumer gate: Mobius

Mobius has a concrete migration seam: resolveAssignedAgentSkills fetches only enabled assignments for one org and agent (agent_skills.go:32-63); agentSkillsPrompt withholds bodies (:65-98); evaluateSkillActions checks required/recommended actions against effective actions (:181-205); prependInvokeSkillTool wires the loader and resolves a name collision (:207-235). The service accepts trimmed names up to 80 bytes, **optional descriptions**, and required bodies; lookup folds case (internal/services/skill.go:316-380). An AgentSkills-only kebab-case/required-description validator would reject valid Mobius records. Its assigned-skill test fixture has a short body (agent_tools_test.go:501-544), while the repository's four document playbooks are 4,978–6,305 bytes (sandbox/skills/{pdf,pptx,xlsx,docx}/SKILL.md); those are realistic Mobius content, but a different skill path, not a production size distribution. A 64 KiB body limit leaves more than 10× room above the largest inspected playbook and must still be checked against stored assigned skills before migration.

Mobius persists invoked **action selectors** in a suspension checkpoint (agent_skill_action_constraints.go:48-95; agent_resume.go:675-712). A bundle digest of name/description/body does not pin those selectors. Dashi's BeforeTool authorization can run for the next call in the same model batch before the previous load settles, even with ToolConcurrency=1 (tools_loop.go:212-231,307-315). Therefore reconstructing Mobius focus only from settled load facts is insufficient for same-batch parity. The initial Dashi package must leave focus state, checkpoint, and authorization order with the host.

## Lessons and evidence limits

1. **Start with the in-memory boundary.** Mobius proves a real host supplies approved definitions after tenancy/assignment checks. Filesystem precedence, resources, shell expansion, and marketplace management can remain source adapters or host behavior. Dive and pi show good discovery UX, but neither requires adding those mechanisms to Dashi's Turn core.
2. **Make disclosure and errors obvious.** Show short names/descriptions first, full body after a named load, and a useful model-facing unknown/unavailable error. Mobius adds an effective action-scope notice so users and the model understand the consequence of loading.
3. **Keep authority separate.** A skill body is lower-trust tool content; allowed-tools prose and Mobius allowed_actions cannot grant execution rights. The host decides catalog placement, tool binding, action authorization, and whether any skill source is trusted as operator text. Pi's project trust and MAF's approvals illustrate the reason.
4. **Pin recovery inputs.** Freeze selected bodies for the turn and incorporate their digest into the agent revision or an equivalent host pin. Continued turns must rebind the same bundle; Dashi's agent comparison alone does not validate unrecorded tool bodies.

No external web claims are used. This comparison does not establish demand for a public file loader, production prevalence, or runtime qualification of the proposed Dashi package.
