# Local MCP client: source review

**Status:** Research snapshot, 2026-09-28. **Roadmap:** [item 6](../remaining-work.md), size M / high difficulty. **Scope:** Dashi connects to an application-managed MCP server and presents its tools as local executors. Provider-hosted MCP and its credential/snapshot boundary are [item 7](../remaining-work.md). Paths below are relative to each named checkout; revisions pin the inspected source.

## Dashi baseline

There is no local MCP client in Dashi at `015b0ec`. `tool.Toolset.Tools(ctx)` supplies definitions and executors before each model call (`tool/tool.go:445-479`); the runner resolves the toolset again before dispatch and requires an identical recorded definition (`runner.go:968-993`, `tools_loop.go:323-346`). This gives an existing protection against changed schemas, but a changing MCP catalog can still fail a pending call. `tool.Definition` preserves raw JSON input schema and advisory annotations (`tool/tool.go:30-158`); `tool.Output` supports ordered `content.Block`s (`tool/tool.go:219-238`, `content/content.go:272-323`). The runner's `Policy.AuthorizeTool` already permits allow/deny/defer and argument rewrites (`policy.go:60-105`); a nil policy allows all bound local tools. Executor errors become model-visible failed outcomes unless marked `tool.Fatal` (`tool/tool.go:387-403`). The example port gap explicitly names local MCP (`design/gaps/F-example-ports.md:230-232`).

Post-snapshot, `main` at `108cb52` replaces `Policy` with `Runner.Hooks.BeforeTool` (`runner.go:21-40`; `hooks.go:84-101`). The hook can allow, deny, defer or rewrite; with no hook opinion, a bound tool runs. The draft [PRD](06-local-mcp-prd.md) uses this merged API.

## Lessons and evidence limits

The smallest useful Dashi surface is an optional MCP-backed `tool.Toolset`, not a second tool policy system. Give each configured server a stable local name, expose a deterministic qualified model name, preserve the original remote name for dispatch, and reject collisions before sending tools to a model. Discovery should page completely and yield an immutable snapshot for the connection; a later refresh belongs **between turns**, since Dashi matches the offered definition at dispatch. Host policy should decide approval using the qualified name and call arguments; MCP annotations are hints, never permission. Keep credentials in caller-owned transport/connection configuration, outside recorded definitions and tool arguments. A network error after dispatch is an **unknown effect**; do not blindly retry a mutating call.

One **blocking correctness gap** needs a small core change: `toolSettlement` converts every returned executor error into a settled failed outcome, even `tool.Fatal`; only an unobserved result after crash/panic is uncertain (`tools_loop.go:435-479`). A lost HTTP response after the MCP server performed a mutation cannot honestly be called a known failure. The client must either prove the call was not sent or report an explicit uncertain outcome that the runner records as `StopUncertain`; it must not retry to find out.

Results must not vanish silently. Map supported text and image/audio blocks to Dashi `content.Block`s, carry `IsError` as a failed outcome, and define explicit behavior for structured content, resources and unsupported blocks. Validate against provider routes separately: Dashi's content type can hold media, but not every model adapter can send every tool-result block. This is source review, not a live MCP server or provider qualification. Eino's external adapter was not inspected, and an unsuccessful search alone was not used as proof of absence.
