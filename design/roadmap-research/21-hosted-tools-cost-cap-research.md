# 21. Hosted tools under a cost cap — research

**Status:** source review, 2026-09-28. **Roadmap:** [remaining work](../remaining-work.md). **Dashi:** `015b0ec56c8d`. This examines a *hard pre-dispatch cost cap* for one model call that can run provider-hosted tools internally; an iteration cap checked after the call is a different guarantee.

## Dashi baseline

Dashi already records hosted request meters (`llm/meter.go`), prices known meters through `Pricing.Requests`, and retains the known subtotal with `UnpricedRequests` when a charge is partial (`llm/pricing.go:145-190,228-250`; [hosted-tool pricing](../hosted-tool-pricing.md)). Adapters prefer final provider counters; when final usage is missing, the runner adds the unpriceable `unreported` meter (`llm/usage.go:44-50`, `budget_accounting.go:11-77`). `Spend.CostPartial` makes that uncertainty visible. Under `MaxCost`, partial cost stops the turn and a budget raise cannot certify it.

`llm.MaxCostAtRisk` refuses a request with a hosted declaration because one provider call can contain additional tool uses and model passes (`llm/risk.go:21-53,94-103`). `checkSendBudget` therefore returns `StopLimited` before dispatch under `MaxCost`, with a reason naming this limitation (`budget_limits.go:14-117`). A host can reserve the admission amount atomically using `ModelAuthorization.Admission` (`policy.go:29-54,86-95`); that does not make an unbounded call bounded. The existing [pricing analysis](../hosted-tool-pricing.md#bounded-admission-deferred-with-evidence) records a live Anthropic probe: `max_uses:1` stopped a second *billable search* yet a further internal pass re-read input. Billed input was 21,440 tokens versus a 9,762-token final context. This is prior Dashi live evidence, not a new probe in this research.

Post-snapshot, `main` at `108cb52` replaces `ModelAuthorization.Admission` with `SendDecision.Admission` from `Runner.Hooks.BeforeSend` (`hooks.go:212-239`). The hard-cap refusal remains the relevant boundary; the draft [PRD](21-hosted-tools-cost-cap-prd.md) uses the merged hook API.

## Lessons and tradeoffs

1. **Price × use count is insufficient.** Anthropic's `max_uses` limits searches, yet refused attempts can still cause another billed model pass. [Anthropic pricing](https://docs.anthropic.com/en/docs/about-claude/pricing) also separates search fees from token billing. A bound needs limits on *passes*, *all uses within a pass*, total token consumption or a provider-enforced spend ceiling, and all fee units. Do not mistake final context size for cumulative billed input.
2. **Route limits have different meanings.** [xAI's `max_turns`](https://docs.x.ai/developers/tools/advanced-usage) limits server-side turns; [xAI's usage details](https://docs.x.ai/developers/tools/tool-usage-details) say one turn can run multiple tools. [OpenAI's `max_tool_calls`](https://platform.openai.com/docs/api-reference/responses) limits processed built-in calls, but the cited contract does not prove that ignored attempts incur no further model-pass charge. These are candidates for qualification, not proof of a dollar cap.
3. **Show the guarantee honestly.** Mobius and OpenHands offer useful seam checks and live spend displays. Dashi's `MaxCost` promise is stronger: it refuses a call whose maximum charge is unknown. Keep known subtotal, unknown meters, and provider-reported versus list-estimated cost distinct for the operator and app ledger. Do not turn a missing final usage frame into a zero bill.

## Evidence and remaining unknowns

The Dashi pricing document's Anthropic data are dated live observations; the competitor rows are source inspections at the listed commits. Official provider documents describe control semantics, but do not by themselves prove a complete maximum USD charge for any route. A first candidate needs dated paid probes and fixtures for sequential uses, refused/ignored uses, parallel uses, truncated streams, all token/cache tiers, and fee units before Dashi admits it under `MaxCost`. No surveyed project supplied a verified universal hosted-call hard cap in this snapshot.
