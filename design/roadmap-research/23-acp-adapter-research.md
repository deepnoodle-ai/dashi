# 23. ACP adapter — source research

**Status:** Draft research, 2026-09-28. **Roadmap:** [item 23](../remaining-work.md), L / high. **Question:** How can an editor use a Dashi Agent without making ACP the owner of Dashi execution state?

## Dashi and protocol baseline

Dashi has no ACP adapter. Its `Turn` is one input through a final or resumable stop; a future Session would join several Turns ([decision 30](../decisions.md)). `Runner.Stream` is a single, lossless owner stream; breaking its range interrupts/cancels work (`runner.go:99-140`). `Observer` has a bounded lossy queue (`policy.go:150-166`; `observer.go:11-35`), so it cannot be an ACP wire source. Committed `Step` facts, `Replay` and `Project` reconstruct model/tool results and current pending work (`turn.go:150-187`; `state.go:124-168`; `project.go:13-185`). Local approval is `DecisionDefer` followed by `Settle{Approval}` bound to call arguments and policy revision (`policy.go:59-96`; `turn.go:345-361`; `runner.go:479-545`). At `015b0ec`, no library Session store or read-after-Seq `Follow` existed; [decision 3](../decisions.md) settles the three delivery classes and cursor direction, while [live-delivery.md](../live-delivery.md) remains a proposal.

Post-snapshot, `main` at `108cb52` has `Runner.Hooks.BeforeTool` in place of `Policy` and implements `StepReader`/`Follow` over committed steps (`hooks.go:96-101`; `follow.go:17-45,112-137`). `Observer` now guarantees committed steps but can drop previews and delivers asynchronously (`observer.go:28-43`). The draft [ACP PRD](23-acp-adapter-prd.md) uses the merged interfaces.

The [current official releases](https://github.com/agentclientprotocol/agent-client-protocol/releases) list stable schema **v1.23.0** and **v2.0.0-alpha.5** (v2 draft). In [v1](https://agentclientprotocol.com/protocol/v1/prompt-turn), `session/prompt` stays pending through work; ordered `session/update` notifications carry message chunks, tool status and usage; the response ends with a limited `stopReason` vocabulary. [V1 `session/load`](https://agentclientprotocol.com/protocol/v1/session-setup) replays retained conversation updates before replying; `session/resume` restores context without replay. Neither is a durable event cursor. [V1 permissions](https://agentclientprotocol.com/protocol/v1/tool-calls) are agent-to-client requests with selectable options; a displayed call is not approval. [V2](https://github.com/agentclientprotocol/agent-client-protocol/blob/128845f5bd4c7fca5f23374e9b4853e470ecf99a/docs/protocol/v2/migration.mdx) instead acknowledges prompt insertion with `messageId`, sends separate `state_update` lifecycle notifications, uses ID-keyed upserts/chunks, and folds load into resume with replay control. These are distinct reducers and completion contracts, not one schema with renamed fields.

One conformance dependency matters: [v1 session setup](https://agentclientprotocol.com/protocol/v1/session-setup) requires agents to accept client-provided **stdio MCP servers**; HTTP and SSE are optional capabilities. Dashi currently lacks a local MCP client ([item 6](../remaining-work.md)). A full ACP v1 agent adapter therefore needs that capability or an equally narrow ACP-side bridge; silently ignoring `mcpServers` would mislead editor users.

## Lessons and evidence limits

The [Zed client source analysis and Dive spike](https://github.com/deepnoodle-ai/dive/blob/65c393f221f1/docs/acpresearch/acp-agent-adapter.md) provide the concrete UX target: announce a tool before asking permission, include a useful title/kind and diff where available, keep IDs stable on load, and replay terminal statuses. Zed prefers load to resume and renders JSON-RPC errors distinctly; it cannot be treated as a generic ACP reducer. ACP v1's `refusal`, `max_tokens` and `end_turn` do not represent every Dashi `Stop` (`failed`, `uncertain`, `waiting`, `limited`), so a truthful adapter needs explicit error/extension handling. `allow_always` requires host-owned policy persistence; OpenHands' unconditional approval illustrates why the permission bridge must fail closed.
