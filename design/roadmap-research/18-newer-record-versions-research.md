# 18. Inspecting newer record versions — comparative research

**Status:** research, 2026-09-28. **Question:** Can an older binary show what was recorded by a newer one without treating unknown facts as executable state?

## Dashi baseline

The [roadmap](../remaining-work.md) marks this M/high difficulty. The [Turn design](../turn.md) already says unknown record kinds may be retained for inspection but must block execution. Current `Step` has a version, kind, sequence, and typed payload fields (`turn.go:182-206`). `Replay` checks **every** step has version 1, correct Turn ID, contiguous sequence, and a known payload/kind; it then applies the step (`state.go:153-190,1210-1239`). `Project` calls that same strict replay before constructing model messages (`project.go:10-38`). `Runner.Run` also relies on replay. This is correct for continuation but leaves an operator without a Dashi-level inspection view.

The file recorder stores each step as JSON in an append-only log, but `Load` decodes each line into typed `dashi.Step` (`filerecorder/filerecorder.go:188-223`; `filerecorder/log.go:185-206`). A plain Go JSON decode discards fields the older struct does not know. Thus adding a lenient `Replay` alone would be both unsafe and lossy: the exact future payload must survive loading if the host is to inspect or export it.

## Lessons and tradeoffs

1. **Preserve before interpreting.** MAF's raw nested fallbacks show how an older reader can round-trip unknown JSON. Dashi's typed `Step` and file-recorder load path need equivalent preservation for an unknown version/kind; a pretty display reconstructed from known fields is insufficient.
2. **Keep two trust levels.** Nvoken and Eino block recovery when execution semantics are unknown. Mobius can still offer a display-safe summary. Pi and Dive show the danger of silently skipping an unrecognized execution record: a resumed agent may miss a prior effect, approval, or accounting fact.
3. **Do not overstate a partial view.** An inspect response may show the last validated known prefix and list later raw steps, but any status, spend, pending call, or transcript after the first unknown step is **not authoritative**. Unknown does not mean corrupt; malformed JSON, broken identity, or invalid sequence should be reported separately.
