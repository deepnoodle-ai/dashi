# Native structured output for model calls: source review

**Status:** Research snapshot, 2026-09-28. **Roadmap:** [item 1](../remaining-work.md). **Dashi references:** [structured turn output](../structured-output.md), [provider gap review](../gaps/E-providers-cost-budgets.md). This is about a direct model call's requested response format. A validated agent *turn* result is a related, existing contract.

## Dashi baseline

`Agent.OutputSchema` and `Start.OutputSchema` define a turn result (`turn.go:41-43, 433-435`). `Runner` appends `dashi_submit_output` with that schema (`runner.go:985-1000`), accepts a schema-valid JSON final text as fallback, and records `StructuredOutput` with source and attempt (`runner.go:1419-1443`; `turn.go:230-246`). The caller reads `Outcome.Output`, rather than parsing the transcript. In contrast, `llm.Settings` has no output format (`llm/llm.go:360-390`), and `llm.Generate` only prepares and sends its `Input` (`llm/request.go:185-198`). No model provider adapter exposes a native JSON Schema response mode. The earlier [gap review](../gaps/E-providers-cost-budgets.md) proposed `Settings.Output`, but predates later Dashi changes; it is a direction, not an approved design.

## Lessons for Dashi

1. **Keep one final-result concept.** Nvoken and Mobius show why callers value a validated object on the turn. Native formatting should become one way to produce Dashi's existing `StructuredOutput` fact, with its schema, source and attempt provenance intact. Direct `llm.Generate` needs its own small result affordance, but the turn API should not gain a parallel `ResponseFormat` contract.
2. **Describe guarantees honestly.** Provider-constrained generation is a request to the provider; local validation is the library's guarantee. ADK's `OutputKey` TODO and Dive's format-only option illustrate the gap. Refusal, output truncation, a tool-call response, unsupported schema keywords, and a malformed final object need distinct observable outcomes.
3. **Make route choice understandable.** ADK's native/tool choice and pi's `prefer`/`require` make capability fallback explicit. Dashi should never silently drop an output schema as an adjustment. Start with native routes that can be qualified; keep the reserved tool for turn/tool combinations where native support is unproven.
4. **Avoid growing a schema DSL.** A caller-authored JSON Schema fits Dashi's existing turn contract. Typed Go decoding can be a helper. Provider-specific schema rewrites must be recorded in the prepared request and must not loosen validation without caller consent.

## Evidence limits

All claims are source review of the revisions above, not live provider tests. Nvoken's working tree has unrelated changes in `generator.go`; the cited generator lines were checked against `git show HEAD` and the other Nvoken paths cited here are clean. Eino provider implementations are in a separate repository. No blanket absence claim is inferred from a search miss; the partial/unknown labels reflect the inspected public paths and examples.
