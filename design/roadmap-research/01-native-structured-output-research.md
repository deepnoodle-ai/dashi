# Native structured output for model calls: source review

**Status:** Research snapshot, 2026-09-28. **Roadmap:** [item 1](../remaining-work.md). Dashi source is `16700d1`; other local revisions are pinned below. This concerns a direct model call's requested response format. A validated agent *turn* result is a separate, implemented contract.

## Dashi baseline and first route

`Agent.OutputSchema` and `Start.OutputSchema` define a turn result. The runner offers `dashi_submit_output`, validates the tool arguments or a JSON final text answer, and records `StructuredOutput` with source and attempt provenance (`turn.go:278-300`; `runner.go:1095-1112,1503-1589`; `output_contract.go:27-116`). The schema is admitted and recorded for recovery ([turn design](../structured-output.md)). `MustOutputSchema[T]` generates a schema for this turn contract (`structured_output.go:15-43`).

Direct calls have no corresponding control: `llm.Input` and `llm.Settings` have no output schema (`llm/llm.go:360-418`); `llm.Generate` just calls `Prepare` then `Send` (`llm/request.go:183-196`). `llm.Result` holds message, stop, usage, cost and raw bytes, but no validated value (`llm/llm.go:500-547`). `RequestSnapshot.Input` and exact `Body` can record a per-call schema without a second request concept (`llm/request.go:12-59`). Crucially, `Agent.Settings` is an `llm.Settings` copied into every runner call (`turn.go:40`; `runner.go:1109-1116`). A schema added to `Settings` would inadvertently request native mode inside turns. `BeforeModel` hooks can replace settings, but not the whole input (`hooks_run.go:49-106`); a direct-only schema belongs on `llm.Input`, guarded again in the runner before `Prepare`.

The first plausible adapter is **OpenAI's public Responses endpoint** (`providers/openai/responses/responses.go:38-124`). `Prepare` maps settings to a body and calls the shared snapshot builder (`:144-176,176-299`); it currently sends local tool schemas with `strict:false` and has no `text.format` mapping (`:228-256`). Streaming terminal events and blocking responses converge on `codec.decode` (`stream.go:215-216`; `responses.go:351-370,618-740`). It distinguishes completed text, refusal, tool use and output limit. `Send` calls `providerhttp.Complete` *after* terminal decoding (`responses.go:351-370`), so a late timeout can invalidate an apparently valid output. An error from `Send` sets `Stop.Kind` to incomplete while retaining the raw provider reason and any usage (`:324-339`). Local validation must run after transport completion. `Message.Text()` concatenates text blocks (`llm/llm.go:320-328`); a native output parser should require one final JSON object, not silently splice separate text parts.

OpenAI's [Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs) specifies Responses `text.format = {type:"json_schema", name, strict:true, schema}`. Strict mode requires an object root, all object properties required, `additionalProperties:false` on every object, and a supported JSON Schema subset; refusal and incomplete responses can break the output contract. The guide supports local references and nested `anyOf`, but its full vocabulary and size limits are larger than a first Dashi adapter needs. The [API reference](https://platform.openai.com/docs/api-reference/responses-streaming/response/refusal?lang=python) constrains `name` to letters, digits, underscores or dashes, at most 64 characters. These requirements are narrower than Dashi's general turn schema validator, which permits optional properties and other JSON Schema 2020 features (`output_contract.go:34-77`). Dive mutates only the root `additionalProperties` field before sending strict mode, so its mapping is useful evidence of the wire shape but not sufficient strict-subset preflight for Dashi (`providers/openai/provider.go:496-540`).

## Lessons and evidence limits

Keep the direct call affordance small: one schema request, one validated final value, and the existing stop/usage/error contract. Provider formatting is generation guidance; Dashi should validate locally. A refusal, tool call or limit is an observable non-output outcome, not a malformed object. Reject strict-incompatible schemas with a path before dispatch; silently converting optional fields can change meaning. Keep the turn's recorded `StructuredOutput` contract and submission tool for now. A native turn path requires separate work on tool compatibility, provenance and recovery.

The OpenAI guide is current documentation, not proof for every model ID or proxy. Dashi's catalog currently has no structured-output feature (`llm/model.go:32-74,231-294`), so model-specific support and a dated live probe remain separate qualification work. Nvoken's working tree has unrelated changes in `generator.go`; the cited generator evidence is from `git show HEAD`. Absence claims are limited to inspected public paths and adapters.
