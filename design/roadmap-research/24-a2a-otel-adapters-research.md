# 24. A2A and OpenTelemetry adapters — research

**Status:** source review, 2026-09-28. **Dashi:** `015b0ec56c8d`. **Roadmap:** [remaining work](../remaining-work.md). A2A is a remote agent task protocol; OpenTelemetry (OTel) is diagnostic tracing. They need different correctness guarantees and should not share a new Dashi “integration framework.”

## Dashi baseline

Dashi has neither adapter. Its `Turn` is an identified sequence of acknowledged `Step` facts (`turn.go:131-203`); `Recorder.Commit` makes those facts authoritative for recovery, accounting, and presentation (`recorder.go:18-67`). `Replay` and `Project` derive state and model messages from that record (`state.go:124`, `project.go:13`). `Runner.Stream` and `Observer` expose committed steps plus provisional deltas/progress (`runner.go:21-39,95-120`, `policy.go:148-166`), but `Observer` is bounded and lossy. A2A state must therefore come from committed facts, never from an observer callback. OTel may lose diagnostics, but needs an execution-time context seam for accurate timing and child HTTP/tool spans; an asynchronous observer alone cannot provide parentage. `Stop` already distinguishes completed, waiting, limited, canceled, interrupted, and failed (`turn.go:361-388`).

Post-snapshot, `main` at `108cb52` adds `StepReader`/`Follow` for committed-step readers (`follow.go:17-45,112-137`). `Observer` now preserves every committed step but can drop previews and remains asynchronous (`observer.go:28-43`). A2A reconnect should use the committed cursor, as the updated [PRD](24-a2a-otel-adapters-prd.md) proposes.

## Lessons, tradeoffs, and evidence boundaries

- [A2A's current specification](https://a2a-protocol.org/dev/specification/) distinguishes task ID from context ID, permits `input-required` continuation on the same task, requires matching IDs, and defines separate canceled/failed/rejected states. Pin the adapter to a released SDK/protocol version when built; do not treat the moving dev specification as a wire-version guarantee. Dive's simple text API is appealing, but broadcasting one plain-text reply to every pending call (`a2a` guide) is unsafe for Dashi's per-call approval identity. An A2A task store may cache a projection; it must not become a second execution journal.
- [OTel's GenAI conventions](https://opentelemetry.io/docs/specs/semconv/registry/attributes/gen-ai/) name `invoke_agent`, `chat`, and `execute_tool` and warn that input messages and tool arguments/results may contain sensitive data. Dive's default-off payload capture and Nvoken's content-free exporter are useful reference points. A span is an observation of one execution attempt; it cannot certify a persisted outcome. A resumed Turn may span multiple traces linked by stable Turn ID, with no synthetic span stretching across downtime.
- **Prioritize OTel first.** Nvoken already consumes Dive/OTel in production-oriented code; a Dashi replacement has a concrete host and a clear privacy requirement. A2A has no confirmed current application use in these checkouts. A narrow Nvoken server pilot is plausible, with Mobius as a potential client, but the product owner should validate that actual exchange before a broad client+server surface is built.
