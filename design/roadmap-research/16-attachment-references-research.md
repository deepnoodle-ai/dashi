# 16. Turn-owned attachment references: comparative research

**Status:** Draft research, 2026-09-28. **Scope:** media/file content in this Turn's input, delivered context, or tool results. Caller-owned prior `History` is a separate storage decision. Paths below are relative to each named checkout. These are inspected local snapshots, not claims about later releases.

## Dashi baseline

Dashi records `Start.Input` and tool outcomes as Turn facts; a tool output can carry `[]content.Block` (`turn.go:333-340`, `tool/tool.go:222`). `Start.History` and `Continue.History` remain caller-owned (`turn.go:427-459`, `runner.go:340-363`, `design/decisions.md:125-139`). `content.Source` currently holds exactly one of inline `Data`, external `URL`, provider `ID`, or provider `URI`; `Origin` binds provider IDs/URIs to a provider and credential/endpoint scope. It has no application-owned reference (`content/content.go:34-96`). A URL is handed to the provider; Dashi does not fetch it. `Resource` is a display/output URI, not a private input resolver (`content/content.go:30-31,253-260`; `design/2026-09-27-resources-and-hosted-tools.md:33-43`).

The Runner projects messages, calls `BeforeModel`, then `Client.Prepare`; `BeforeSend` sees the prepared request (`runner.go:962-1019,1086-1114`). A `ModelFact` records `RequestDigest = digest(req.Body())`, not the body, before dispatch (`runner.go:1143-1174`; `turn.go:281-310`). `llm.RequestSnapshot` itself contains input and exact body bytes in memory (`llm/request.go:12-32,138-145`); it is **not** persisted in that fact. This is a natural place to resolve references on a detached input before `Prepare`, while leaving the record small and retaining exact-request evidence. The earlier `design/history-storage.md:155-187` proposes that direction but is not a settled contract; it also allows signed URLs and provider IDs that cannot be byte-verified through the proposed digest.

## Lessons and tradeoffs

1. **Mobius demonstrates the missing boundary.** The host decides who may access an artifact and whether it still exists; the library can retain the opaque ref in facts and ask again at each model call. A digest catches accidental or malicious byte substitution, but cannot replace authorization. A cache must not bypass the authorization recheck (`document_hydration.go:407-434,517-528`).
2. **Refs must not become URLs by accident.** Dive, Eino, MAF, and OpenHands support URLs or provider IDs, but those are delivery locations with different expiry, authorization, and byte-verification properties. Dashi's existing provider `Origin` solves provider replay scope, not app access control.
3. **Make failure visible before dispatch.** Mobius rejects missing/expired/deleted attachments and even residual checkpoint refs. OpenHands's fallback to the original URL is pragmatic for public image links, but a private attachment must not silently disappear or fall back to a stale location.
4. **Keep recorded and delivered forms separate.** Nvoken pins bytes at admission; Mobius keeps refs and produces a temporary delivered copy. Dashi can use its prepared-request digest to prove which exact body was sent without persisting hydrated bytes. The resolver contract must define host retention across pause/resume and recheck access on each preparation.

**Evidence limits:** “No native ref” means absent from the inspected public content types and paths, not a repository-wide proof. Provider acceptance of any URL, file ID, or MIME type varies and is not qualified here. Nvoken's cited media and turn files were checked against its `deea133a` HEAD; its unrelated dirty `internal/adapters/divegen/generator.go` was not used. Dashi HEAD is `015b0ec`.
