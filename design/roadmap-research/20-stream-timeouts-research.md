# 20. Connection and idle-stream timeouts: comparative research

**Status:** Draft research, 2026-09-28. The source table describes inspected local checkouts, not later releases. “Model stream” means provider response consumption; browser live-update sockets are a separate connection.

## Dashi baseline and timeout meanings

`internal/providerhttp.Client.Post` creates `http.Client{Timeout: 5 * time.Minute}` unless a provider config supplies a client; it sends once, with no redirect or internal retry (`internal/providerhttp/http.go:204-260`). That total timeout covers a slow response as well as a healthy long stream. There is no separate response-start or stream-read idle timer in this shared HTTP path. `llm.Stream` yields deltas and one terminal result/error, and breaking the iterator cancels its call context (`llm/stream.go:14-75`).

A **Turn deadline** is different: `Limits.Deadline` derives the Runner context, and expiry records `StopLimited`; a host context ending normally records `StopInterrupted` (`runner.go:304-313,628-667`; `design/turn-interruption.md:145-164`). During a model call, Dashi records partial text/content and observed usage on **parent-context interruption**. Its ordinary transport-error branch does not synthesize those partial deltas if the provider returns an empty partial result (`runner.go:1195-1268,1270-1300`). Settlement estimates missing usage for accounting (`budget_accounting.go:129-137`). A transport error with unknown dispatch is settled as uncertain, not silently retried (`runner.go:1270-1334`). A new idle timeout therefore needs a small partial-result fix, not just a timer.

| Timer | What it bounds | Current Dashi situation |
|---|---|
| Response start | Request dispatch through response headers, including DNS, TCP, TLS, upload, and provider header wait; it does **not** identify which phase stalled | Only the five-minute total timeout or host context |
| Total model call | All elapsed time, even while response bytes keep arriving | Five-minute `http.Client.Timeout`; custom client may differ |
| Stream read idle | Time blocked waiting for the next response-body bytes after headers or prior bytes | No watchdog; a stalled stream waits for total/host timeout |
| Application Turn deadline | Whole Turn across model calls, tools, and waits, persisted as a limit | Existing `Limits.Deadline`; `StopLimited` |

## Lessons and evidence limits

Pi demonstrates the developer benefit of naming connect and idle separately. Mobius and Nvoken show why a timeout must retain its **scope**: a provider read stall, a step deadline, and the Turn's durable deadline should not appear to users as the same cancellation. ADK Go shows the total-call trap: a healthy stream can expire, and the consumer's own work can count toward its timeout. Dashi has the right settlement and uncertainty facts, but transport-timeout handling must also salvage already observed deltas rather than add hidden retries.

“Not found” above is limited to inspected types and adapters, not repository-wide absence. Browser reconnect behavior is not evidence of model transport guarantees. Nvoken's cited `generator.go:281-296,410-440` was verified at HEAD; its unrelated working-tree change is elsewhere in that file. All other citations were inspected at the listed commits; Dashi HEAD is `015b0ec`.
