# 20. Connection and idle-stream timeouts: comparative research

**Status:** Revised research, 2026-09-28. Dashi was rechecked at `018af90`; the comparison table describes the pinned local checkouts, not later releases. “Model stream” means provider response consumption; browser live-update sockets are a separate connection.

## Dashi baseline and timeout meanings

`internal/providerhttp.Client.Post` creates `http.Client{Timeout: 5 * time.Minute}` unless a provider config supplies a client; it sends once, with no redirect or internal retry (`internal/providerhttp/http.go:204-260`). A custom client's `Timeout` replaces that default, including with zero. The total timeout covers a slow response as well as a healthy long stream. There is no separate response-start or stream-read idle timer in this shared HTTP path. `llm.Stream` yields deltas and one terminal result/error, and breaking the iterator cancels its call context (`llm/stream.go:14-75`).

A **Turn deadline** is different: `Limits.Deadline` derives the Runner context, and expiry records `StopLimited`; a host context ending normally records `StopInterrupted` (`runner.go:304-313,628-667`; `design/turn-interruption.md:145-164`). During a model call, Dashi records partial text/content and observed usage on **parent-context interruption**. Its ordinary transport-error branch does not synthesize those partial deltas if the provider returns an empty partial result (`runner.go:1261-1374`). `ModelFact` stores a free-text `Error` and a dispatch `Failure`, but no typed timeout reason (`turn.go:338-382`). It is JSON cloned and validated as part of the existing step record (`turn.go:633-655`; `state.go:592-635`), so an optional reason field fits without a new record model. Settlement estimates missing usage; usage that was reported before a failed stream is not currently flagged partial merely because the stream ended early (`budget_accounting.go:11-56,129-137`). A transport error with unknown dispatch is settled as uncertain, not silently retried (`runner.go:1334-1374`). A new idle timeout therefore needs partial-result and accounting fixes, not just a timer.

| Timer | What it bounds | Current Dashi situation |
|---|---|
| Response start | Request dispatch through response headers, including DNS, TCP, TLS, upload, and provider header wait; it does **not** identify which phase stalled | Only the whole-client timeout or host context |
| Total model call | All elapsed time, even while response bytes keep arriving | Five-minute `http.Client.Timeout` only for the default client; a supplied client wholly replaces it |
| Stream read idle | Time blocked waiting for the next response-body bytes after headers or prior bytes | No watchdog; a stalled stream waits for total, custom-client, or host timeout |
| Application Turn deadline | Whole Turn across model calls, tools, and waits, persisted as a limit | Existing `Limits.Deadline`; `StopLimited` |

## Lessons and evidence limits

Pi demonstrates the developer benefit of naming connect and idle separately. Mobius and Nvoken show why a timeout must retain its **scope**: a provider read stall, a step deadline, and the Turn's durable deadline should not appear to users as the same cancellation. ADK Go shows the total-call trap: a healthy stream can expire, and the consumer's own work can count toward its timeout. Dashi has the right settlement and uncertainty facts, but transport-timeout handling must also salvage already observed deltas rather than add hidden retries.

### Actual Dashi adapter boundary

OpenAI Responses, OpenAI Chat Completions, and Anthropic Messages call `providerhttp.Post`; Grok and Meta wrap Responses, DeepInfra, Mistral, and OpenRouter wrap Completions, and Ollama wraps Messages (`providers/{grok,meta,deepinfra,mistral,openrouter,ollama}/*.go`). These nine public constructors form one bounded HTTP model surface. Gemini uses the Google SDK's `GenerateContent` / `GenerateContentStream`, with its own guarded `RoundTrip`, and does **not** dispatch through `providerhttp.Post` (`providers/google/gemini/gemini.go:486-563`; `sdk.go:180-255`). Image/video clients also have separate transports. Giving any of those clients the same option without enforcing it would be misleading; the first slice should omit the option there and document the boundary.

An idle timer belongs around each raw `Body.Read`, not the SSE parser's next decoded event: comment and heartbeat bytes are real network activity, and application time between reads is not provider idleness (`internal/sse/sse.go:51-103`). A response-start timer must cover `Client.Do` through headers only, while preserving the context for the response body. A custom `http.Client` can impose a shorter independent timeout, so only Dashi-owned timer expiries can always receive a precise Dashi timeout reason. Stream parsers currently wrap read errors as transport errors; the timeout cause must survive those wrappers (`providers/openai/{responses,completions}/stream.go`; `providers/anthropic/messages/stream.go`).

“Not found” above is limited to inspected types and adapters, not repository-wide absence. Browser reconnect behavior is not evidence of model transport guarantees. Nvoken's cited `generator.go:281-296,410-440` was verified at HEAD; its unrelated working-tree change is elsewhere in that file. Competitor citations were inspected at the listed commits.
