## Highlights

Dashi v0.15.1 fixes switching models in the middle of a conversation. The
public API is unchanged.

Before, a conversation that started on an OpenAI reasoning model, such as
GPT-6, failed on its next Turn after a switch to another model. The error was
`opaque content requires its original destination` or `private replay data
has no lossless canonical conversion`. A Turn now drops what the new model
cannot read: OpenAI's private reasoning, its answer-phase marker, and
completed provider-hosted tool work such as web searches and approved MCP
calls. Your own tool calls and their results are kept. Each drop is recorded
in the model call's `ContentChanges`. A `BeforeModel` hook can still make the
Turn strict.

In the CLI, a mouse selection no longer vanishes when a tool call inside it
finishes, so Ctrl+C copies it instead of interrupting the Turn.

A session saved before this release can still fail to switch after GPT-6,
because its reasoning was saved in a form that cannot be dropped. Start a new
session to switch models. Upgrade with `brew upgrade deepnoodle-ai/tap/dashi`.

## Changelog

### Fixed

- **Switching model after a GPT-6 answer works.** GPT-6 marks each answer with
  `"phase": "final_answer"`. Preparation refused to drop that marker for
  another model, so the next Turn failed with `private replay data has no
  lossless canonical conversion`. The documented phases, `commentary` and
  `final_answer`, are now dropped and recorded as `strip_replay`. An
  unfamiliar phase still stays on OpenAI.
- **Switching model or provider mid-conversation works after a reasoning
  model.** A Turn now omits reasoning and completed provider tool work (such
  as OpenAI web searches, and answered MCP approval requests with their
  responses) that the new destination cannot replay, and records
  each omission in the model call's `ContentChanges`. Before, the next call
  failed, for example `opaque content requires its original destination`
  after switching from GPT-6 to Meta. A `BeforeModel` hook can still make the
  policy strict. Direct `Client.Prepare` calls stay strict by default.
- **Omission no longer leaves two user or two assistant messages in a row.**
  When omission empties a message, for example one that held only an OpenAI
  web search, its neighbors now join into one message so roles still
  alternate. Messages that were already adjacent, and messages with tool
  results, stay as they were.
- **GPT-6 reasoning is recognized.** Responses reasoning items with an empty
  `content` array, as GPT-6 sends, decode as reasoning instead of opaque
  content.
- **A mouse selection in the CLI no longer vanishes when a tool call in it
  ends.** Since tool rows read as phrases, a row's text changed from
  `Reading a.go…` to `Read a.go` as the call ended, which cleared any
  selection across it; Ctrl+C then interrupted the turn instead of copying.
  A tool row's text is now copyable only once its call ends.
